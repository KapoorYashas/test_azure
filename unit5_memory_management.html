5.1

Basic Concepts — Logical & Physical Address Map

Memory management is the OS function that manages the primary memory (RAM). It keeps track of each byte in memory, allocates and deallocates memory to processes, and ensures protection between processes.

Why Memory Management?

  • Multiple processes must coexist in RAM simultaneously.
  • Each process needs its own isolated address space.
  • Efficient utilization of limited physical memory is critical.
  • Provides illusion of unlimited memory via virtual memory.

Logical Address (Virtual Address)

Definition An address generated by the CPU during program execution. Also called virtual address. The process uses logical addresses; it has no knowledge of physical memory layout.
  • Generated by the CPU for every memory reference.
  • Starts from 0 for every process (each process has its own address space).
  • The set of all logical addresses is the Logical Address Space.

Physical Address

Definition The actual address in RAM where the data resides. Managed by the Memory Management Unit (MMU).
  • The set of all physical addresses is the Physical Address Space.
  • Physical addresses are not directly visible to user processes.

Address Translation (MMU)

The Memory Management Unit (MMU) is a hardware device that maps logical addresses to physical addresses at runtime.

5.2

Memory Allocation

Contiguous Memory Allocation

Each process occupies a single contiguous block of memory. Memory is divided between the OS (low memory) and user processes (high memory).

Fixed Partition (Static Partitioning)

Fixed Partitioning Memory is divided into fixed-size partitions at boot time. Each partition holds exactly one process.
✅
Advantages
Simple to implement. Easy to manage. Low OS overhead.
❌
Disadvantages
Internal fragmentation is severe. Number of partitions limits degree of multiprogramming.

Variable Partition (Dynamic Partitioning)

Dynamic Partitioning Partitions are created dynamically as processes arrive. Each process gets exactly as much memory as it needs.

Allocation Strategies:

StrategyMethodBest For
First FitAllocate first hole that is big enoughSpeed
Best FitAllocate smallest hole that is big enoughMin waste
Worst FitAllocate largest hole availableLarge leftover

Internal Fragmentation

Internal Fragmentation Wasted space inside an allocated partition. Occurs in fixed partitioning when process is smaller than partition.
Example Partition size = 100 KB, Process size = 82 KB Internal Fragmentation = 100 - 82 = 18 KB (wasted inside partition)

External Fragmentation

External Fragmentation Total free memory is enough but scattered in non-contiguous holes. No single hole is large enough. Occurs in dynamic partitioning.
EXTERNAL FRAGMENTATION — Small scattered holes cannot serve large process

Compaction

Compaction The OS shuffles memory contents to place all free holes together, forming one large contiguous block. Solves external fragmentation but is expensive (requires relocation).
  • Only possible if relocation is dynamic (done at execution time).
  • High overhead — all processes must be moved.
  • Alternative: Paging (eliminates external fragmentation entirely).
5.3

Paging

Principle of Operation

Paging is a non-contiguous memory allocation scheme that eliminates external fragmentation.

  • Page: Fixed-size logical memory blocks (e.g., 4 KB).
  • Frame: Fixed-size physical memory blocks of same size as page.
  • Any page can be mapped to any free frame — no external fragmentation!
  • A Page Table maintained per process maps page → frame numbers.

Address Structure in Paging

A logical address is divided into two parts:

Logical Address Structure [ Page Number (p) | Page Offset (d) ] If logical address space = 2^m, page size = 2^n: Page Number = m - n bits Page Offset = n bits
Physical Address Calculation Physical Address = (Frame Number × Page Size) + Page Offset = (PageTable[p] × 2^n) + d

Hardware Support for Paging

Page Table Register (PTBR)
Points to the page table in memory. On context switch, only PTBR needs to be changed.
TLB — Translation Lookaside Buffer
A fast hardware cache for page table entries. Converts 2 memory accesses to ~1 on a TLB hit. Hit ratio typically > 98%.
Effective Access Time (EAT) with TLB EAT = (TLB hit ratio × 1 memory access) + ((1 - hit ratio) × 2 memory accesses) Example: hit ratio = 0.98, mem access = 100ns EAT = 0.98 × 100 + 0.02 × 200 = 98 + 4 = 102 ns

Page Allocation

  • OS maintains a free-frame list.
  • When a process arrives, OS allocates n free frames (where n = ⌈process size / page size⌉).
  • Page table is filled with corresponding frame numbers.

Protection & Sharing in Paging

Protection: Each page table entry has protection bits:

  • Valid bit: 1 = page in logical space, 0 = illegal access → trap to OS.
  • R/W/X bits: Control read, write, execute permissions per page.

Sharing: Multiple page tables can point to the same frame (shared code/libraries). Each process has its own page table for private data.

Disadvantages of Paging

Key Drawbacks
  • Internal fragmentation — last page may be partially filled.
  • Page table can be very large (32-bit addr, 4KB pages → 1M entries).
  • Every memory access requires 2 memory accesses (page table + actual data) unless TLB is used.
  • No concept of "logical grouping" — code and data cannot be easily separated.
5.4

Virtual Memory — Basics, Hardware & Control Structures

What is Virtual Memory?

Virtual Memory A technique that allows execution of processes that may not be completely loaded in physical memory. Gives the illusion of a very large memory to each process.
  • Only the currently needed portions of a program reside in RAM.
  • Rest of the program lives on disk (swap space / page file).
  • Enables programs larger than physical memory to run.
  • Increases degree of multiprogramming — more processes can be active.
  • Implemented mainly via Demand Paging.

Benefits of Virtual Memory

📦
Large Programs
Run programs bigger than physical RAM.
🔗
Shared Memory
Shared libraries loaded once, mapped into multiple virtual spaces.
⚡
Fast Process Creation
Fork() can use copy-on-write — no immediate copying of pages.

Hardware Support

Virtual memory requires hardware + OS cooperation:

ComponentRole
MMU (Memory Mgmt Unit)Translates virtual to physical addresses using page tables
TLBCaches recent virtual→physical translations for speed
Valid/Invalid BitMarks whether a page is currently in RAM or on disk
Page TablePer-process mapping of virtual pages to physical frames
Disk (Swap Space)Secondary storage holding pages not currently in RAM

Control Structures

  • Page Table: Virtual page number → frame number + control bits (valid, dirty, referenced).
  • Inverted Page Table: One entry per frame (indexed by frame number), saves space for large address spaces.
  • Swap Space Table: Tracks disk location of each swapped-out page.
  • Frame Table: OS-maintained table of all physical frames (free/occupied).
5.5

Locality, Page Fault, Working Set & Demand Paging

Locality of Reference

Principle of Locality Programs tend to access the same set of memory locations repeatedly over a short period of time. This makes caching (TLB, page frames) effective.
🕐
Temporal Locality
A recently accessed item is likely to be accessed again soon. Example: loop variables accessed repeatedly.
📍
Spatial Locality
Items near recently accessed items are likely to be accessed. Example: sequential array traversal, instructions in a loop.

Page Fault

Page Fault Occurs when a process tries to access a page that is not currently in RAM (valid bit = 0). The OS must load it from disk.

Page Fault Handling Steps:

  • CPU generates page fault trap → OS takes control.
  • OS checks if reference is valid (legal address?). If not → abort process.
  • Find a free frame. If none, use a page replacement algorithm.
  • Schedule disk I/O to load the required page into the free frame.
  • Update page table (set valid bit = 1, record frame number).
  • Restart the faulting instruction.

Working Set Model

Working Set W(t, Δ) The set of pages used by a process in the last Δ time units (the working set window). A process needs all its working set pages in memory to run efficiently.

Dirty Page / Dirty Bit

Dirty Bit (Modified Bit) A bit in the page table entry. Set to 1 when a page is written to (modified in RAM). When this page must be replaced, it must be written back to disk. If dirty bit = 0 (clean), no write-back needed — saves disk I/O.

Demand Paging

Demand Paging Pages are loaded into memory only when demanded (on first access). No page is loaded until it is needed.
  • Lazy loading — reduces startup time of processes.
  • Works hand-in-hand with virtual memory and page fault handling.
  • Requires valid/invalid bits in page table.
  • Pure demand paging: Start with zero pages in RAM; load each on first access.
  • Performance: Effective access time = (1 - p) × memory access + p × page fault service time, where p = page fault rate.
Effective Access Time EAT = (1 - p) × ma + p × page_fault_time Where: p = page fault rate (0 ≤ p ≤ 1) ma = memory access time (~200ns) page_fault_time ≈ 8ms (disk seek + latency + transfer) To keep EAT < 10% degradation: p < 1/400,000

Page Replacement Algorithms

When a page fault occurs and no free frame is available, the OS must select a victim page to evict. The algorithm to choose the victim is the page replacement algorithm. Goal: minimize page faults.

Idea Replace the page that will not be used for the longest time in the future. Gives minimum possible page faults. Theoretical — requires future knowledge (used as benchmark).

2. FIFO — First In First Out

Idea Replace the page that has been in memory the longest (oldest arrival). Maintain a queue of pages; evict from the front.

  • Suffers from Bélády's Anomaly — more frames can cause more page faults!

Bélády's Anomaly In FIFO (and some others), increasing the number of frames can sometimes increase page faults. Not a problem with OPT or LRU (stack algorithms).

3. Second Chance (SC) Algorithm

Idea Modified FIFO. Each page has a reference bit (R). When a page is referenced, R=1. On replacement: check oldest page — if R=0, evict it; if R=1, give it a second chance (reset R=0, move to end of queue), continue.
  • Also called Clock Algorithm (pages arranged in circular buffer with clock hand).
  • Avoids evicting frequently used pages unlike pure FIFO.
  • Approximates LRU without the expensive timestamp tracking.
  • If all pages have R=1, degenerates to FIFO (all get second chance).
CLOCK / SECOND CHANCE — Circular Buffer with Clock Hand
Clock hand points to next candidate. R=0 → evict. R=1 → reset to 0, advance hand.

4. NRU — Not Recently Used

Idea Classify pages into 4 classes using Referenced (R) and Modified (M) bits. Evict from the lowest-priority class first.
ClassReferenced (R)Modified (M)Priority
Class 000Best victim (evict first)
Class 101Not referenced, but dirty
Class 210Referenced, not dirty
Class 311Worst victim (evict last)
  • R bits are cleared periodically (on each clock tick/interrupt).
  • Evict a random page from the lowest non-empty class.
  • Simple approximation of LRU. Prefers clean (M=0) pages since no disk write needed.

5. LRU — Least Recently Used

Idea Replace the page that has not been used for the longest time. Based on temporal locality — past use predicts future use.
  • Optimal in practice — very close to OPT performance.
  • Does not suffer from Bélády's Anomaly (it's a stack algorithm).

Implementation Approaches:

Counter / Timestamps
Each page table entry stores a timestamp of last access. On replacement, evict page with smallest timestamp. Expensive to search all entries.
Stack (Doubly Linked List)
Maintain a stack of page numbers. On access, move page to top. Evict from bottom. O(1) removal with doubly-linked list + hash map.
